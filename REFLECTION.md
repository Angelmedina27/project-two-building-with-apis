## Project #2: Building With APIs

<b>1. Defend your research decision</b> I was between two options for my API provider which were TMDB or TVMaze. TVMaze was good for several reasons, one of them being that there was no API key needed nor a sign-up. However, TVMaze on covered TV. TMDB, the provider I ended up using, on the otherhand, allowed both tv and movies. Though TMDB is a little stricter on the terms of non-commercial use only with the fact that you need to add their logo to every page, it is the better option for me.

<b>2. Explain one prototype decision</b> In my prototype, "prototypes/watchlist-edit.html", I wanted to test how the My Watchlist page and item editing flow should look and work before writing the real Django templates. In this prototype I was able to see the watchlist table with an inline status dropdown and a separate detail page for rating and notes which looked simple and easy to manage. After opening the prototype in my browser and testing everything, I picked variant A because it kept the main watchlist less cluttered and easy to scan while also allowing me to change a movie's status in that same place. That decision appears in my finished app on the "My Wishlist" page where each row has an inline HTMX status dropdown and clicking a title opens its dedicated edit page where you can rate the movie or tvshow.

<b>3. Trace your API update</b> The update I chose was to update my saved record for "Dune: Part Two (2024)", changing its rating field from "None" to "8". First, "config/urls.py" routes "/api/" requests into "watchlist/api/urls.py". Next the view that handles it is "WatchlistItemViewSet" where it then passes the data to the serializer that validates it which is located at "WatchlistItemSerializer" in "watchlist/api/serializers.py". Finally, I verified that the change was saved by checking the output printed in my terminal which showed that the rating was indeed changed to 8 next to *Dune: Part Two*.

<b>4. Trace and verify your data</b> The page that I choose that browses saved records is the My Watchlist page. The "watchlist" view in "watchlist/views.py" grabs only the logged-in user's saved items from the line of code "(WatchlistItem.objects.filter(user=request.user))" and passes them into the "filter_watchlist" inside "watchlist/filters.py". If I type into the search box (`q`), the filter checks for matching movie or show titles using "queryset = queryset.filter(title__icontains=filters["q"])", and when I use the dropdowns it narrows the list down by status and media type. It then sorts the list using the whitelisted "SORTS" options in "watchlist/filters.py". After that, "watchlist/views.py" uses Django's `Paginator` to split the matching items into pages of 10 while keeping my active search and filter settings in the page links. When I tested filtering by `On Hold` in the browser, it returned "Iron Man (2008)", which matched directly because we can see on my watchlist page that movie is indeed on hold.
